# Adaptive Hybrid Music Playlist Recommendation using Reinforcement Learning

Final-year mini-project for two courses: **Recommendation Systems** and **Reinforcement Learning**.

A hybrid recommender (Popularity, Content, Item–Item CF, ALS, fused with Reciprocal Rank Fusion) generates
~88 candidates per user. An RL agent then builds a 5–20 track playlist step by step by choosing one of 10 global
content clusters at each step. Six agents are compared: Random, Greedy, UCB1, LinUCB, Q-Learning, SARSA.

No deep learning, no SVD/SVD++ (the data is implicit feedback), and no RMSE/MAE anywhere. `SEED = 42` throughout.

## Pipeline

```
Music_Info.csv (50,683 tracks)      User Listening History.csv (9.71M rows)
        └───────────── join on track_id ─────────────┘
   clean + merge duplicates → iterative k-core → 40,000-user subsample → re-core
        → 39,825 users × 11,613 tracks, 1,489,288 interactions, leave-5-out split
   content vectors (9 quantile-normalised audio features + 100-term TF-IDF tags)
   Popularity · Content · Item-item CF (k=5) · ALS
        → NDCG-weighted Reciprocal Rank Fusion → ~88 candidates per user
   RL layer: agent picks a content cluster per step → 5–20-track playlist
        → evaluation (P/R/F1/NDCG/MAP/HR @10,20 + beyond-accuracy) → Streamlit demo
```

## Key results

Mean over 5 folds of 1,000 unseen users, 5 held-out tracks per user (full tables in
[`report/FINDINGS.md`](report/FINDINGS.md) and `results/final_comparison.csv`).

| Model | Recall@20 | NDCG@20 | HitRate@20 |
|---|---|---|---|
| Popularity | 0.0469 | 0.0325 | 0.1738 |
| Content | 0.0633 | 0.0459 | 0.2422 |
| ALS | 0.2479 | 0.1759 | 0.6234 |
| Item–Item CF | 0.3909 | 0.3345 | 0.8104 |
| Hybrid (RRF) = Greedy | 0.3976 | 0.3187 | 0.8220 |
| Hybrid + Q-Learning | 0.3192 | 0.2022 | 0.7623 |
| Hybrid + SARSA | 0.3256 | 0.2152 | 0.7659 |
| Hybrid + UCB1 | 0.3535 | 0.2193 | 0.7792 |
| Hybrid + LinUCB | 0.1357 | 0.0825 | 0.5030 |

Findings:
- Collaborative filtering does nearly all the work; the hybrid is a good candidate generator (candidate recall@100 = 0.5573).
- **The RL result is negative:** no learned agent beats the plain hybrid ranking on any accuracy metric.
- LinUCB games the simulated reward: highest reward, but a hit rate of 0.32× Random's.
- Genre labels do not help (55.9% missing, 46.5% agreement with the track's own tags).

Limitations, post-hoc changes to the plan, and caveats (3 training seeds, results cover only users with ≥ 20 listens)
are disclosed in `report/FINDINGS.md`.

## Reproducing

Each stage is a module under `src/` and writes its outputs to disk. See `docs/SPEC.md` Part D for the phase order
and each phase's acceptance criteria. In order:

```bash
python -m src.eda                       # Phase 0: reproduce dataset statistics
python -m src.data_prep                 # Phase 1: clean, k-core, subsample, split
python -m src.features                  # Phase 2: content vectors
python -m src.recommenders.hybrid       # Phases 3–4: base models + RRF hybrid (see also evaluate_phase3/4)
python -m src.rl.fit_global_clusters    # Phase 5: fixed global song clusters
python -m src.rl.train                  # Phase 6: train the RL agents
python -m src.evaluation.evaluate_all   # Phase 7: 11-config comparison
python -m src.evaluation.figures        # figures
python report/build_findings.py         # Phase 9: regenerate report/FINDINGS.md
```

Check each module's `--help` or docstring for options; some stages take arguments.

## Demo

Needs `data/processed/` and `models/` to exist (no training happens in the app).

```bash
streamlit run app.py
```

Pick a user, an agent, and a playlist length; each playlist is a single frozen-policy rollout.
